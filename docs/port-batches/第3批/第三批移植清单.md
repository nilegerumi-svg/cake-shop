# 第三批移植清单（8 道 v53 新增配方下沉 · 桥退为纯投影）

> 承接 `第二批移植清单.md`「已知限制」第 2 条：8 个 v53 独有配方当时只在
> `js/host/tm-bridges.js` 里补了名称用于「最爱」显示，配方本体没下沉到数据层。
> 本批把它们按仓库既有 schema 正式落进 `js/data/recipes/`，并让桥不再持有数据。
> 依据：仓库既有层级（`js/data/recipes/` 放配方、`js/data/index.js` 汇总、
> `js/host/` 放运行时手写块）。**不新造目录、不覆盖既有配方、不动 bundle 分片。**
> 性质：**增量批次**，不是最终包。

## 一、方向调整：为什么没做「熟客簿写入回写」

第二批遗留第 1 条本是本批的头号候选，探查后判定**不能在 host 层干净收尾**，
故本批不做，理由如实记录：

| 发现 | 证据 |
| --- | --- |
| `readState()` 每次 `JSON.parse` 返回**新对象** | `tm-bridges.js` 第 29–41 行；`people.js` 的 `s2.coins -= 5`、`s2.regulars = ...` 改的是临时副本 |
| 写入连即时生效都没有 | 本批浏览器实测：面板 12 个「登记 ¥5」按钮，点击后存档 `coins 9959 / regulars 0` **完全不变**，无 dialog、无报错 |
| 仓库主程序**没有熟客系统** | 拼回的 bundle 中 `regulars` **0 处**，「熟客」4 处均为 NPC 台词与一条随机事件文案；`__TM_STATE_GET__` 0 处 |
| v53 侧有完整逻辑 | v53 中 `regulars` 53 处、`__TM_STATE_GET__` 5 处 |

也就是说，即便在 host 层补一个写回钩子，登记出来的 `regulars` 也**没有任何主程序消费**
（不会触发熟客来店、不会累计 `regularsSold` / `regularsEarned`），而 `coins` 还会与
主程序内存态双写打架。v53 之所以能写，是因为它的 getter 挂在 React 根组件作用域、
返回活 state；仓库的压缩 bundle 拿不到那个引用。**要完整复现必须动 bundle 层**，
属于需要单独评估的批次，本批不做一个「能点但没效果」的假闭环。

### 为什么用「独立键 + 汇总时并入」

`js/data/index.js` 的 `DATA_MODULES` 是 `Promise.all` **并行加载**，
`v53_additions.js` 与 `merged_for_game.js` 的先后无法假设；若在新文件里直接
`Object.assign(Cake.RECIPES_GAME, ...)`，可能被随后执行的 `merged_for_game.js`
整表赋值覆盖。因此新文件只挂独立键 `RECIPES_GAME_V53`，等 `__cakeDataReady`
完成后在 `index.js` 统一并入，并对已存在的 id **跳过不覆盖**（只新增）。
这与仓库「子模块各自挂载、index 汇总」的既有写法一致。

桥的 `wait()` 增加等待 `RECIPES_GAME.macaron`，保证投影物品表时 8 道已并入，
`__TM_ITEM_MAP__` 不再依赖任何硬编码。

## 三、一个「不搬」的发现：126 项 baseCost 调价

把 v53 物品表 199 项与仓库三表（`INGREDIENTS_GAME` / `RECIPES_GAME` / `ITEMS`）
逐字段比对，除 8 项独有外，**另有 126 项 `baseCost` 不同**，且 v53 普遍更高：

| 配方 | v53 | 仓库 | 比值 |
| --- | --- | --- | --- |
| `cappuccino` | 106 | 52 | 2.04 |
| `butter_cookie` | 70 | 40 | 1.75 |
| `blueberry_cake` | 166 | 95 | 1.75 |
| `burger` | 147 | 88 | 1.67 |
| `banana_bread` | 74 | 70 | 1.06 |

已确认 v53 的 `baseCost` 是源码里**静态字面量**（11419 行起逐条写死），
不是运行时按食材推算，因此这确实是一次逐项经济平衡调整，而非动态值。

**本批不搬**，原因：这是大面积覆盖仓库已跑通的定价数据，会连带影响烘焙成本、
售价、成就与经济平衡，且与第一批「`pc-layout.css` 不覆盖、保留仓库成果」同一性质。
需要你确认是「v53 有意调价、应当跟进」还是「两条分支口径不同」，再决定单独开一批处理。
另有少量零散差异（`taste` 1、`ings` 2、`shelfDays` 2、`unlockCost` 2、
`bakeCost` 2、`category` 2、`emoji` 1），同样留待评估。
