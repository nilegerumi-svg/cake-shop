# 逆向源码说明（js/src）

> 原 `app.bundle` 是 1.8MB 的**压缩打包成品**（无 source map）。已用 acorn 在**顶层语句边界**切分、prettier 美化，按功能域归入 `js/src/` 下的 10 个域文件夹、共 **53 个模块文件**（合计 ≈2.64MB，美化后体积变大属正常）。其中超 100KB 的模块又按「声明 / 语句 / 数据段」边界做过一轮再切，切点全部落在语义边界（详见下节「大文件拆分」）。

## 这是「逆向」不是「反编译」——必须知道的边界

- **变量名 / 注释 / 原始目录结构无法恢复**：压缩时已被丢弃，没有原始注释，也没有原始目录结构。但标识符已做**系统性语义还原**（详见下节「符号还原」）：现有名称是按代码行为重新拟定的英文名，不是原名。
- **全部分模块属同一作用域**：它们只是把一条连续字节流切成可读片段，跨文件引用照旧。模块边界落在「语句边界」，但一个大函数内部不会跨文件，单文件可独立阅读。
- **运行保真**：53 个模块按 `TM_SOURCE_PARTS` 顺序拼接，与切分前的 43 模块拼接**语义等价**（大文件拆分处的校验见下节），离线浏览器实测 `#root` 挂载、`pageerror 0`、四批移植成果无回归。

## 加载方式

`js/app.bundle.js` 是手写加载器：按 `TM_SOURCE_PARTS` 的 53 项顺序 `fetch` `./src/` 下各模块，拼成 Blob 后作为 ES 模块 `import`（保留顶层 `await` 与模块作用域）。原 `js/app.bundle/` 目录已删除，分片不再落盘。

## 运行时结构：外壳 + iframe 面板

界面**是 iframe 架构**，但不是「每个页面各跑一份应用」，而是「一份 JS 跑在外壳里，DOM 分散渲染进各 iframe」。

```
index.html（外壳，宿主窗口）
├─ js/data/index.js     数据层
├─ js/app.bundle.js     加载器 → 拼接 53 个 js/src 模块 → 执行
├─ #root                React 根（首页 / 顶栏 / 弹窗 / 底部 tab 都在这里）
└─ css/game.css         UI 主样式（入口，@import 拆出的分片）

pages/<id>/index.html（6 个面板文档，真正的 iframe）
├─ #container > #root   空壳，只有挂载点
├─ js/frame-bootstrap.js 错误上报 / 主题同步 / 焦点保存
└─ css/frame-base.css   面板基础样式（入口，@import 拆出的分片）
```

- **面板清单**：`home`（店面）、`market`（农贸市场）、`town`（小镇）、`fate`（通讯，已并入手机 App）、`profile`（人物志）、`achieve`（成就档案），对应底部 tab 的 `frameId`。
- **渲染方式**：`PanelFrame`（`meta/02`）渲染 `<iframe src="pages/<id>/index.html">`，`onLoad` 时取 `contentDocument`，用 `ReactDOM.createRoot(iframeDoc.getElementById('root'))` 把 React 树**跨文档**渲染进去。所以业务逻辑、状态、`window.Cake` 全部在父窗口；iframe 内不加载 `app.bundle.js`，只有一个空 `#root` 和一段引导脚本。
- **生命周期**：懒创建——首次 `active` 才建 iframe；之后靠 `display:none / block` 切换，不销毁（保留滚动位置与内部状态）。
- **跨文档通信**：父窗口用 `postMessage` 下发 `frame:theme`（夜间/盲人模式/字号）与 `frame:command`（如 `town:open-map`）；子文档用 `frame:ready` / `flash-app-error` 回报。
- **访问限制**：同源（相对路径），父窗口可直接读 `contentDocument`；反过来 iframe 内**拿不到** `window.Cake`，写面板逻辑时要按「组件 props 传参」来，不要指望全局。
- **样式为什么有两套**：`game.css` 管外壳与全局 UI，`frame-base.css` 管面板文档（iframe 内的 `html`/`body`/滚动容器）。两者都把内嵌的 Material Icons 字体外置到了 `css/fonts/material-icons.woff2`，改面板样式要去 `css/frame-base/`，改外壳去 `css/game/`。

## 符号还原（压缩名 → 语义名）

在拆分完成后，对标识符做了一轮**跨文件全局改名**：`acorn` 解析 + `eslint-scope` 作用域分析，只改解析到「全局/模块作用域」的那一个符号——声明处改 `defs`，各文件的引用改 `through`；函数内部的同名局部变量（`e`/`n`/`s` 这类形参）完全不动。每批改名后都跑浏览器回归（`pageerror 0` + 四批移植数据比对）。

| 指标 | 数值 |
|---|---|
| 全局标识符总数 | 1878 |
| 已还原为语义名 | 1853（≈98.7%） |
| 仍为短名 | 25（7 个是定义了但从未被引用的死常量；3 个是 `Map`/`Set`/`NaN` 内置对象，属统计误报；1 个是 `shop/03` 的 `c`，属**原包自带缺陷**，见下；其余为浏览器 / UMD 全局如 `Howler`、`getComputedStyle`） |

> **`shop/03` 的 `c` 不是改名遗留**。`processIngredient()` 里 `const c = INGREDIENT_MAP[a.out]` 声明在 `if (!a.packOnly) {…}` 块内，而函数末尾 return 的提示语引用了 `c`。原始压缩源码逐字如此（`if(!a.packOnly){const c=re[a.out],…}`），属上游既有 bug，改掉就偏离原包行为，故保留原样、仅作记录。

**2026-11-14 修正**：此前把「只在调用处出现、全仓库无定义」的 12 个短名判为「原包裁掉分片的死分支」，这个判断是**错的**。它们在原始 12 个分片里全都有定义，实际是改名时**定义改了、引用没跟上**（`gi`→`PanelFrame`、`dF`→`AchievementPanel` 等 9 处）。这些位置恰好都在首次进入游戏后才渲染的组件里，而当时的校验只等到 `#root` 有子节点（标题页即满足），所以一直没暴露——表现为进游戏后落到错误边界「游戏出了点小问题 / `gi is not defined`」。9 处已全部修复，校验脚本也补了「进入游戏 + 检测错误边界文本 + 检查 iframe 内已渲染」三项断言。


改名的收益是**读得懂**：`Eo`→`GLOBAL_OBJECT`、`Zc`→`playActiveTrack`、`Nf`→`clearTrackFadeTimer`、`t`→`jsxRuntime`、`q`→`React`、`Hc`→`stopSpeech`、`_e`→`announce`（语音播报主入口）、`advanceToNextDay`（日结算主流程）等。

约定：

- **改名必须全局一致**。所有模块拼接后共享同一作用域，`Je` 这种符号可能在 A 文件定义、B 文件引用；只改一处会炸运行时（曾因此触发 `Je is not defined`，已回滚改为跨文件改名）。
- **新名不得与现有全局符号重名**。重名会被跳过（脚本会打印 `⚠ 冲突跳过`），需换一个更具体的名字再跑。
- 局部变量、形参仍是 `e`/`n`/`s` 这类单字母。它们作用域短、不影响阅读，且逐个改会显著增加 diff 噪声，暂不处理。

## 维护约定

- **新增 / 修改功能**：直接在对应域文件夹改文件；若新增模块，在 `TM_SOURCE_PARTS` 的对应**顺序位置**插入路径。
- **切勿调整顺序**：拼接顺序改变会破坏运行。
- **换行约束**：`.gitattributes` 已对 `js/src/*/*.js` 设 `text eol=lf`，仅限 LF。
- 想读懂某段逻辑：用语义名（如 `announce`、`advanceToNextDay`、`NPC_SCHEDULES`）在 `js/src/` 内全局搜索（`grep -rn`），按域文件夹缩小范围。
- 少部分符号仍是短名（见上节表格），照旧可搜。
