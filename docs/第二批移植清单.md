# 第二批移植清单（数据桥 + 档案增量）

> 承接 `第一批移植清单.md` 的「已知遗留」第 1 条：3 个数据桥缺失，
> 人物志显示「共 0 人」。本批把数据接通，并补回 v53 相对仓库新增的档案字段。
> 依据：仓库既有层级（`js/data/characters/npcs/` 放镇民数据、
> `js/host/` 放运行时手写块、`js/data/index.js` 并行加载、`docs/` 放接线文档）。
> **不新造目录、不改命名规则、不动 bundle 分片。**

## 一、先做的比对（不靠目录名猜）

用本地浏览器把 v53 主界面与仓库 `window.Cake` 的完整数据 dump 后逐项比对：

| 发现 | 数据 |
| --- | --- |
| 镇民 id | v53 `Zt` 58 人 ∩ `Cake.NPCS` 58 人 = **58，零差异** |
| 数据新旧 | **v53 更全**：`giftLine`/`loveGiftLine`/`dateLine` 58 vs 34、<br>`rels` 51 vs 24、`hiddenRels` 24 vs 0、`homeArea` 24 vs 2 |
| 物品表 | v53 199 项，仓库 `INGREDIENTS_GAME`+`RECIPES_GAME`+`ITEMS` 覆盖 191 |
| 存档键 | 仓库 bundle 与 v53 同用 `sweet-offline-saves`，**可直接读同一份存档** |

这个结论推翻了「写个桥把仓库旧数据投过去就行」的最初想法 —— 那样会丢掉
v53 后来补的隐藏关系、送礼台词和关系网，人物志会显示 58 个退化版的人。

逐字段比对后确认：**51 人需补、7 人完全一致、零值冲突**，全部是纯新增字段，
不会覆盖仓库任何既有值（`homeArea` 在 v53 中多为 null 占位，已过滤不搬）。

| 文件 | 动作 | 说明 |
| --- | --- | --- |
| `js/data/characters/npcs/profiles_v53.js` | 新增 | 51 位镇民增量档案，只补缺失字段、绝不覆盖 |

### 四个桥的接法

| 桥 | v53 原本 | 本批实现 |
| --- | --- | --- |
| `__TM_NPC__` | 框架区 `Zt`，挂 React 根组件作用域 | 从 `Cake.NPCS` 投影为数组（58 人） |
| `__TM_ITEM_MAP__` | 框架区 `ge` 物品对照表 | 合并 `INGREDIENTS_GAME` / `RECIPES_GAME` / `ITEMS` / `PRODUCTS` 为 `id→{name}`，8 个 v53 独有配方名兜底 |
| `__TM_AFF_GET__` | 返回活 state 的 `s.affection` | 从 `sweet-offline-saves` 读 `main.affection`（**双重序列化，需二次 parse**） |
| `__TM_STATE_GET__` | 返回活 state `s` | 从同一存档读 `main` |

`__TM_LONG_PROFILES__`（长档案）与 `__TM_WALL_SCROLL__`（文案墙滚动）由第一批
`long-profiles.js` / `wall.js` 自带，本批不动。

**数据仍只有一份**：全部落在 `js/data/`，bridge 只是投影，符合 README 的
「bundle 直读 `window.Cake.*`，不设中间适配层」。仓库的压缩 bundle 无 `__TM_*`
注入点（全为 0 处），改不了内部，故只在 `js/host/` 做一层只读桥。

桥用 `setTimeout` 轮询等 `Cake.NPCS` 齐备再投影 —— `js/data/index.js` 是
`type=module`（defer），同步的 host 脚本会先执行，必须等数据层。

## 三、验证（本地 http + 无头浏览器，带真实存档进主界面）

- `#root` 挂载 ✅，**pageerror 0**，**console.error 0**
- `__TM_BRIDGES_READY = true`
- `__TM_NPC__` = **58 人**（第一批时为 0），人物志实际点开渲染 **58 行**
- 档案字段：`rels` 51 人、`giftLine` 58 人、`hiddenRels` 1 人
- 「最爱」从 id 变成中文名（芒果慕斯 / 草莓蛋糕 / 马卡龙），物品桥生效
- `__TM_AFF_GET__()` 返回 `{xiaotian:0, ahe:0, xiaomei:0}`
- **隐藏关系门槛实测**：好感 0 → 不显示；改到 240 → 显出「义卖摊的旧相识…」，
  两档均零报错。证明隐私机制完整接上，不只是把数据挂上了
- 3 个新文件语法校验通过（`index.js` 按 ES module 校验）

## 四、已知限制与后续

1. **`__TM_STATE_GET__` 是只读快照，不回写**：v53 里它返回 React 活 state，
   熟客簿会直接改 `s.coins -= 5` / `s.regulars = ...`；仓库没有那个引用，
   本桥从 localStorage 读，熟客簿能正确显示，但「登记熟客」写入不会持久化。
   要完整复现需接回 React state 或补一个存档写入钩子，留待后续批次。
2. 8 个 v53 独有配方只在物品桥补了**名称**用于「最爱」显示，没有把配方本体
   下沉到 `js/data/recipes/`（不影响本批功能，属数据层接线范围）。
3. `__TM_LONG_PROFILES__` 目前仍是空占位（v53 也是空），长档案「♥」标记与
   sections 待内容填充。
4. 第一批清单里的第 3、4 条（bundle 内部手写注入、397 个待下沉静态对象）
   仍属 bundle / 数据层，本批未触碰。
